{# --------------------------------------------------------------------------- Breadcrumb macro for the six project-scoped pages. Before this, the crumbs read 项目 / 成员管理 — which tells you what kind of page you are on but not *which project*, the one thing you actually need when six pages share one layout. editor.html and audit.html had no crumb block at all and fell through to base's 测试平台, so the two pages where you are deepest in the hierarchy were the two that told you nothing. The project name is filled in by crumb.js, not by the server: these routes are deliberately thin shells and the API (`GET /projects/`, guarded by `_project_and_role(..., "project.view")`) is what enforces membership. Rendering the name server-side would mean duplicating that permission check in the page layer — a second place to get authorisation wrong. The ships with the id as placeholder text so the crumb is never empty. --------------------------------------------------------------------------- #} {% macro project_crumb(project_id, label) -%} 项目 / 项目 #{{ project_id }} / {{ label }} {%- endmacro %}
