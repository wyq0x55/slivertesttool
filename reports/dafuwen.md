## 二、核心玩法

每名玩家创建记录卡时，需要秘密设置：

- 财富目标
- 名誉目标
- 快乐目标

默认规则为：

财富目标 + 名誉目标 + 快乐目标 = 60 分

财富按照配置规则换算为分数。默认可采用：

财富每 1,000 元 = 1 分

但如果当前仓库已有不同换算规则，以当前代码为准。

玩家在游戏过程中不断更新：

- 当前现金
- 当前名誉
- 当前快乐
- 当前职业
- 当前薪级
- 职业经历

只有当财富、名誉、快乐三个维度同时达到各自预设目标时，玩家才达成“幸福人生”。

不能只根据总分大于等于 60 判定成功。

例如，玩家目标为：

- 财富 20 分
- 名誉 20 分
- 快乐 20 分

即使实际状态是：

- 财富 40 分
- 名誉 20 分
- 快乐 0 分

也不能判定为获胜，因为快乐目标没有达到。

## 三、目标隐私

财富、名誉、快乐的目标值默认是秘密信息。

目标值只能被以下角色读取：

- 玩家本人
- 可选的房主或裁判，是否可见由房间设置决定

其他普通玩家不能通过：

- 页面
- API
- Realtime 数据
- 浏览器开发工具中返回的 JSON

读取其他玩家的目标值。

不要仅在前端隐藏目标。必须在服务端查询、API 返回和数据库权限上控制。

公共玩家列表可以显示：

- 昵称
- 头像或颜色
- 在线状态
- 当前职业，可由房间配置是否公开
- 当前薪级，可由房间配置是否公开
- 是否已经达成幸福人生

默认不要公开玩家具体目标值。

当前现金、名誉和快乐是否公开，应设计成房间级配置，默认可以公开当前值，但不公开目标值。

必须实现：

创建者输入：

- 房间名称，可选

- 邀请链接
- 二维码

房主自动加入房间。

### 加入房间

玩家可通过：

- 房间码
- 邀请链接
- 二维码

加入房间。

加入时填写：

- 昵称
- 头像或颜色
- 自己的财富目标
- 自己的名誉目标
- 自己的快乐目标

实时校验三个目标是否符合房间规则。

### 中途加入

游戏开始后仍可允许玩家加入。

中途加入时：

- 不重置已有玩家数据
- 新玩家创建独立记录卡
- 按房间设置获得初始现金、名誉、快乐和薪级
- 由房主选择新玩家从标准初始状态开始，或者手动设置当前状态
- 系统记录加入事件
- 新玩家不能读取其他玩家的秘密目标
- 玩家在实体棋盘上的位置不由应用自动决定

房主可以关闭或重新开启中途加入。

### 断线重连

刷新页面或短暂断网后，应恢复：

- 房间身份
- 玩家身份
- 自己的秘密目标
- 当前记录卡
- 历史记录
- Realtime 订阅

不能只使用 React 内存状态。

## 七、获胜判定

实现独立的纯函数判断：

1. 将当前现金转换为当前财富分数
2. 判断财富分数是否达到财富目标
3. 判断名誉是否达到名誉目标
4. 判断快乐是否达到快乐目标
5. 只有三项都满足时，才判定为达成幸福人生

达成后：

- 显示庆祝动画
- 在房间事件中记录达成时间
- 可选择继续游戏或由房主结束游戏
- 不自动暴露玩家秘密目标
- 不自动把其他玩家踢出房间

不得默认使用“总资产最高”或“最后未破产玩家”作为胜利条件。
